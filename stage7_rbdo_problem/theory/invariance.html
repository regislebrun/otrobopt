Pushforward, invariance and canonicalization¶

This page states the law-determined property, the pushforward identity, the invariance theorem, the existence and measurability conditions, the parameter-dependent construction and the discretization used by the canonicalizer.

Law-determined measures¶

Definition 1 (Law-determined measure)

A measure functional is law-determined if implies whenever both sides are defined.

The mean, the variance, the mean-standard-deviation tradeoff, the quantile, the joint chance measure and the individual chance measure are law-determined by construction: each is an integral, a root of a distribution function, or a monotone transform of such a quantity. The worst-case measure is law-determined once the support of the law and the optimization domain are fixed, because it is the extremum of a continuous function over that set.

The property is not automatic. A pathwise maximum over a fixed sample is not law-determined: it depends on the sample, not only on the law. This is the reason the worst-case measure needs an explicit support and domain policy, and the reason a sample-average approximation is a numerical method rather than a measure.

Existence and joint measurability¶

For a continuous distribution , a transport exists. One construction is the Rosenblatt transform composed with its inverse; another is the quantile transform in dimension one; the DistributionTransformation class provides the isoprobabilistic constructions. The transport need not be unique and need not be invertible: only the pushforward equality matters.

When is a decision variable, the map must be jointly measurable and must be a Caratheodory function, so that is a well-defined function of . The isoprobabilistic constructions are expected to satisfy this condition on the feasible parameter domain, except at singular values such as a zero scale or a singular correlation matrix. Those values are excluded by the parameter bounds. Joint measurability is not needed for the pointwise theorem; it is needed when is optimized, and it is stated here as an assumption rather than claimed without proof.

The implementation uses two reference policies. The standard fast path applies when has a parameter-free standard distribution , for example a normal with fixed standard parameters. The normal fallback uses with when the fast path is not available. A worst-case measure needs an additional domain policy because the support is part of the model; see Parameter-dependent distributions and canonicalization.

Parameter-dependent distributions and canonicalization¶

The parameter of the family is the active distribution parameter . The full parameter vector also contains fixed or qualified coordinates, typically the dependence or copula block. The active indices are available through ; the default policy keeps every parameter active except the trailing dependence block exposed by Distribution.getParametersCollection, because OpenTURNS does not provide an analytic parameter derivative for that block. The user can override the selection with setActiveParameter on the transformation or with CanonicalizationOptions.activeParameter on the canonicalizer.

The class CanonicalizationOptions controls the reference, the active parameter, the parameter bounds, the parameter starting point and the worst-case domain. Bounds and starting points are expressed in active coordinates; a full-dimensional value is accepted as a compatibility fallback and is filtered to the active coordinates.

The reference selection follows these rules.

  • AUTO uses an explicit reference when one is set, then the standard fast path when it is available, and then .

  • STANDARD requires the standard fast path and rejects a user reference.

  • NORMAL forces and rejects a user reference.

  • USER_REFERENCE requires an explicit reference.

  • USER_DOMAIN uses the automatic reference policy and requires a worst-case domain.

When optimizeParameter is false, or when the active parameter is empty, the parameter is frozen and the distribution is used directly as the reference. When it is true, a worst-case measure fails closed unless the standard fast path, a bounded user reference or an explicit domain is available. The policies STANDARD, NORMAL, USER_REFERENCE and USER_DOMAIN make the choice explicit.

The robust problem rejects mixed measure distributions. If the objective measure and the reliability measure use different distributions, the canonicalizer cannot choose one parameter vector ; the error points to the aggregation construction. The same check is applied recursively inside an AggregatedMeasure. A vector-valued robust objective is rejected as well.

The limitation is that the blocks must be independent; dependent blocks must be described by a single joint distribution.

The main failure modes are:

  • a stale or wrong transport, so that ;

  • a reference that still depends on , for example a standard distribution whose degrees of freedom are not fixed;

  • a support mismatch for the worst-case measure, where the mathematical extremum is preserved but the numerical domain is not;

  • a discrete or mixed distribution, which is outside the continuous transport assumption;

  • unaggregated parameter blocks, which the canonicalizer rejects;

  • a vector-valued robust objective, which the problem rejects;

  • a measure that was discretized before canonicalization, so that the distribution parameter is no longer available;

  • a shallow copy of an aggregate measure, which does not rebuild its children;

  • a sign flip in a chance constraint, which turns the constraint into its complement;

  • numerical equality assumptions: the theorem is exact, but quadrature, sampling and finite differences are not.
